# download-benchmark

Консольный скрипт на Python для замера скорости скачивания. Он делает 10 последовательных GET-запросов к указанному адресу, на каждый дожидается полного ответа и считает:

- среднее время одного запроса;
- общий объём скачанных данных;
- скорость скачивания.

Внешние зависимости не нужны, только стандартные библиотеки.

## Требования

Python 3.8+.

## Запуск

```bash
python3 benchmark.py <URL>
```

### Пример:

```bash
python3 benchmark.py https://proof.ovh.net/files/10Mb.dat
```

Это тестовый файл, который хостинг OVH публикует специально для проверки скорости. Подойдёт и любой другой крупный файл или картинка. Некоторые сайты (например, Wikimedia) отвечают на запросы скрипта ошибкой `429 Too Many Requests`: они ограничивают обращения без своего идентификатора клиента и частые запросы подряд. В таком случае возьмите адрес с публичного тестового хостинга или собственный сервер.

### Необязательные параметры:

| Параметр | Описание | По умолчанию |
|---|---|---|
| `-n`, `--requests` | число запросов | 10 |
| `-t`, `--timeout` | таймаут сетевых операций, секунды | 30 |

## Пример вывода

```
Запрос 1/10: 4.25 МБ за 0.812 с
...
Запрос 10/10: 4.25 МБ за 0.790 с

Среднее время запроса: 0.801 с
Скачано всего:         42.50 МБ
Скорость скачивания:   5.31 МБ/с
```

## Единицы измерения

- Время: секунды (с).
- Объём: мегабайты (МБ), 1 МБ = 1 000 000 байт (десятичная система, не МиБ).
- Скорость: мегабайты в секунду (МБ/с). Чтобы получить Мбит/с, умножьте на 8.

## Как считается скорость

Скорость = общий объём всех ответов / суммарное время всех запросов. Паузы между запросами и запуск скрипта в расчёт не входят. Время каждого запроса измеряется от отправки до получения последнего байта тела ответа.

## Ошибки

Если запрос завершился ошибкой (HTTP-статус не 2xx, таймаут, нет соединения), скрипт выводит сообщение в stderr и завершается с кодом 1, не печатая итоговой статистики.

## Тесты

```bash
python3 -m unittest -v benchmark_tests
```

Тесты используют только стандартную библиотеку и локальный HTTP-сервер (интернет не нужен). Они проверяют:

- по умолчанию делается ровно 10 запросов, и они идут последовательно (одновременных соединений не бывает);
- скрипт дожидается полного ответа (на «медленном» эндпоинте время запроса не меньше задержки сервера);
- в выводе есть среднее время запроса, общий объём и скорость в МБ/с, и числа согласованы между собой;
- опция `-n`, ошибки HTTP, недоступный сервер, некорректный URL и `-n 0`.
